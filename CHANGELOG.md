# Changelog

## Unreleased

### Skills

- **install-reviewer** — Added `--override` flag for upgrading existing scaffolded reviewer files in place (#35). Without `--override`, the skill runs in install mode (current behavior; Step 2 refuses if any of the four target files exist). With `--override`, the skill switches to upgrade mode: a different feature branch (`feat/upgrade-coding-policy-review`), a different commit message and PR title (`ci(review): upgrade ...`), preflight skips the branch-clear checks (the upgrade branch may legitimately already exist from a prior in-flight upgrade attempt) and instead refuses if any of the four target files have uncommitted local edits — mirrors how `git pull` refuses to overwrite a dirty working tree, forces the consumer to commit/stash before the scaffold replaces their files; scaffold snapshots ALL four target files (sources + locks) before the cp/compile and restores them on compile failure (extending the existing `actions-lock.json` snapshot+rollback contract); commit/push pick the upgrade branch automatically. Each of the four scripts (`preflight.sh`, `scaffold.sh`, `commit.sh`, `push.sh`) accepts `--override` as a positional argument (parsing is order-independent across `$@`) and emits an `override: bool` field in its JSON output so callers can verify the mode they're running under. SKILL.md adds a "two modes" preamble plus per-step bash blocks showing both invocations; the description's "Use when..." clause now lists upgrade trigger phrases (`upgrade`, `update`, `refresh`, `pull latest reviewer templates`, `override`). Fixes the unblocking pain consumers had on every prior fix in this changelog: today the only options were manually `git rm`-ing four files, hand-backporting fixes (defeating the managed-scaffold contract), or accumulating drift.
- **install-reviewer** — OpenAI reviewer prompt now treats the PR's changed-files list as a closed allowlist for inline-comment paths (#32). Codex was hallucinating inline-comment paths outside the PR diff (e.g., posting on `tile.json:3` when the diff only touched `.github/workflows/*`); GitHub rejected the resulting `create_pull_request_review_comment` calls with HTTP 422 ("Path could not be resolved"), which cascade-failed the subsequent `submit_pull_request_review` so the substantive verdict never landed on the consumer's PR. The workflow's safe-outputs handler caught the API error gracefully — masking the failure as a green run with no review posted. Hard fix: Step 3 now explicitly extracts `CHANGED_FILES` from `gh pr view --json files`; Step 5 instructs the agent to validate `path` against `CHANGED_FILES` before each `create_pull_request_review_comment` call (drop the inline comment and fold the finding into the review body if the path doesn't match); Guardrails restate the constraint with the concrete failure mode (422 → cascade-fail). Same change mirrored in the dogfood `.github/workflows/review-openai.md`. Anthropic-side reviewer not affected (Claude wasn't observed hallucinating paths), but the same `CHANGED_FILES` allowlist could be added defensively if the failure mode ever appears there.
- **install-reviewer** — Three quick-fix bundle for issues surfaced from real consumer installs (#30, #33, #34). (a) `scaffold.sh` post-compile sanitization extended: in addition to stripping per-line trailing whitespace (already there), it now collapses trailing whitespace at EOF (`\n\n` → `\n`) via `perl -i -0pe 's/\s+\z/\n/'` so consumer working trees don't ship lock files with the blank-EOF-line drift gh-aw's compiler emits — both forms violate `rules/code-formatting.md`'s "Basics" and were causing reviewer noise on consumer PRs (#30). (b) `engine.env` now coalesces `CODEX_API_KEY` and `OPENAI_API_KEY`: `OPENAI_API_KEY: ${{ secrets.CODEX_API_KEY || secrets.OPENAI_API_KEY }}`. gh-aw's compiled validation step accepts either name, but the Codex CLI / API-proxy path only reads `OPENAI_API_KEY` at runtime; without the fallback, a consumer who set `CODEX_API_KEY` only would pass validation and then fail with empty-credential after burning setup time (#33). (c) The `network.allowed` block's comment in `review-openai.md` no longer claims the allowlist gates `tessl install`. The install runs in the workflow's `steps:` on the runner host, BEFORE the awf sandbox starts; the allowlist applies to agent-runtime traffic only (gh / MCP / API calls + Codex UI/telemetry). Pure doc fix; the host list itself is unchanged (#34). All three fixes mirrored into the dogfood `.github/workflows/review-{openai,anthropic}.md` where applicable; lock files recompiled and sanitized.
- **release** — Reframed Copilot from a temporary trial that retires "once gh-aw is validated" to a deliberate second reviewer kept indefinitely. The two have complementary lenses: gh-aw enforces `rules/*.md` compliance (its prompt loads each rule file and checks the diff against it), while Copilot reads for doc accuracy, cross-step consistency, and ambiguity that no rule file specifically targets. PR #29's review cycle made the case in production: Copilot caught outdated model IDs, unpinned install commands below floor, Step 5/Step 7 contradictions, vacuous-pass loopholes in the merge gate, and `pull_request` trigger ambiguity — none of which were rule violations gh-aw could flag. SKILL.md description, Step 4 phrasing, and Step 6 re-run language updated; the "Trial — keep Copilot in parallel" framing replaced with "Also request Copilot." `GH_AW_DETAILS.md` updated to explain the dual-lens design and drop the "retires once gh-aw is validated" language. Step 7's merge gate is unchanged — it already required `state != none` for both reviewers.
- **install-reviewer** — Reviewer setup now installs the tile under `/tmp/gh-aw/coding-policy/` instead of `~/.tessl/` (`--global`). Diagnosed against a real consumer install on 0.2.2: the OpenAI reviewer was failing every PR with `Policy load failed: $HOME/.tessl/tiles/jbaruch/coding-policy/rules/ is missing or empty`. Two constraints have to hold simultaneously — `actions/checkout`'s default `clean: true` rules out a workspace-local install, and the awf firewall sandbox the agent runs inside doesn't mount `${HOME}`, which rules out `--global`. Switching the install root to `/tmp/gh-aw/coding-policy/` satisfies both: it's gh-aw's canonical runtime directory (where it also keeps its own prompt and logs, so the awf sandbox is already wired to read from there), and it lives outside the workspace so `actions/checkout`'s clean leaves it alone. Implementation moved from `pre-steps:` to top-level `steps:` so the install runs AFTER gh-aw's `Create gh-aw temp directory` step (which creates `/tmp/gh-aw/`); pre-steps were too early. The agent prompt now hardcodes `/tmp/gh-aw/coding-policy/.tessl/tiles/jbaruch/coding-policy/...` — `${{ runner.temp }}` isn't on gh-aw's safe-expressions list for prompt bodies. The fix supersedes the 0.2.0 #23 fix that introduced `--global` — that change closed the actions/checkout-wipe gap but accidentally moved the install outside the awf sandbox's mount set.
- **install-reviewer** — `.mcp.json` neutralization landed (#15). The Anthropic reviewer template now sets `engine.args: ["--strict-mcp-config"]`, which tells Claude Code to load only the MCP servers gh-aw injects via its own `--mcp-config` and ignore any project-local `.mcp.json` the consumer ships. The previous workaround (preflight `root-mcp-json-present` warning + asking the consumer to gitignore the file) is removed: the warning is gone from `preflight.sh`, the related "Known limitation" paragraph in `review-anthropic.md` is replaced with a one-line note pointing at the fix, and the SKILL.md descriptions of the warning are dropped. Requires gh-aw >= v0.71.0 (where `engine.args` was added) and Claude Code CLI >= 2.1.x (where `--strict-mcp-config` was added); the gh-aw floor is already enforced by preflight from #22. The same flag is mirrored into this repo's dogfood `.github/workflows/review-anthropic.md` so the dogfood reviewer is robust against a future committed `.mcp.json`. Lock files recompiled.
- **install-reviewer** — Four consumer-install bugs fixed (#21–#24). (a) `review-openai.md` `network.allowed` now lists the gh-aw ecosystem identifiers `github` (covers github.com / codeload / raw / objects) and `threat-detection` (covers api.github.com), plus `chatgpt.com` and `ab.chatgpt.com` for the Codex engine's UI/telemetry hosts — Codex's `defaults` allowlist excludes all of these, which was blocking `tessl install` on the OpenAI cross-family review for every claude-authored PR (#21). The same allowlist plus the `edited` trigger were also applied to this repo's own dogfood reviewers in `.github/workflows/review-{openai,anthropic}.md`, with lock files recompiled on gh-aw v0.71.0 — without that, every dogfood PR review would keep hitting the same firewall noise. (b) Pre-steps now run `tessl install jbaruch/coding-policy --global --yes` so the tile installs to `~/.tessl/` (outside the workspace) instead of `.tessl/` (inside) — gh-aw runs pre-steps before `actions/checkout`, whose default `clean: true` was wiping the workspace-relative install before the agent could read it (#23). The Step 2 prompt path is now `$HOME/.tessl/tiles/jbaruch/coding-policy/rules/`. (c) `pull_request: types` now includes `edited` so the gate re-fires when a contributor adds a missing `**Author-Model:**` line via PR-body edit instead of forcing an empty commit (#24.1). (d) Step 1's "Otherwise" fallthrough now spells out all three branches (both paired families present, neither paired family present, only the other paired family present) — the neither-family case was previously implicit and read as an oversight. (e) Step 5 violation-citation form changed from `rules/<name>.md` (a non-resolving consumer-repo path) to `` `jbaruch/coding-policy: <rule-name>` `` so PR-comment readers see a tile-prefixed name instead of a broken link (#24.3). (f) `preflight.sh` now checks `gh aw --version` >= v0.71.0 with a concrete pin command (`gh extension remove gh-aw && gh extension install github/gh-aw --pin v0.71.0`) — github/gh-aw marks every release from v0.69.0 onward as prerelease, so `gh extension install github/gh-aw` installs v0.68.3 (the latest stable), which compiles lock files with the deprecated Claude SDK `bypassPermissions` flag (#22). The Anthropic workflow's `.mcp.json` known-limitation comment dropped its specific gh-aw version reference now that the floor moves with consumer installs.

Per-scenario wins from the tuning pass: Coverage Gap 74 → 100 (+26), Review Response 85 → 97 (+12), Copilot via GraphQL 89 → 97 (+8), PR Merge Cleanup verified at 99 (held). ### Skill tuning (driven by eval log analysis)

- **eval-authoring** — Step 7 (Fill Coverage Gaps) now spells out the `criteria.json` wrapper format (`{context, type: "weighted_checklist", checklist: [...]}`) with a code example, requires `max_score` weights to sum to exactly 100, and warns against mirroring plain-array seed fixtures from the test repo under evaluation. Step 7 also makes the Steps-4–5 review/fix loop explicit for newly-authored scenarios — the prior "Repeat Steps 4–6" got skipped on self-authored content. Step 5 (Fix Issues) now states that a misaligned, leaking, or otherwise unsalvageable criterion must be **removed and the remaining criteria reweighted to sum to 100** — bumping a bad criterion's weight to keep the math tidy makes the scenario worse, not better. Eliminated the Coverage Gap regression (74 → 100) and the Quality Audit "increase the misaligned criterion's weight" failure mode.
- **install-reviewer** — Step 1 (Preflight) now states the gh-aw extension's canonical owner in SKILL.md prose (`gh extension install github/gh-aw`, with an explicit note that the extension lives under the `github` org, not the tile owner). Previously this string lived only inside `preflight.sh`'s failure message, where the agent overlooked it and substituted `jbaruch/gh-aw` from tile-owner pattern-matching.
- **release** — Step 2 (Create PR) and Step 7 (Merge + Cleanup) each gained a "When wrapping this step in a reusable script" paragraph: scripts that automate PR creation must enforce the tile's readiness gate (tests + linter), construct/validate the conventional-commits title format, and preserve the exact `**Author-Model:**` line (with the bold-marker literal); scripts that automate merge must enforce the same pre-merge gates the agent does (CI green, every bot review `APPROVED` or non-blocking `COMMENTED`, no unresolved threads), use `git branch -d` (never `-D`) for the local-branch delete, and verify the publish workflow fired before printing the final summary. Step 6 (Address Feedback) reinforces the prescribed reply literals: accept replies must begin with the literal phrase `Fixed in <sha>` (`Done` / `Resolved` / `Accepted and fixed` do NOT satisfy); decline replies must begin with `Declining — <reason>` using a U+2014 em dash followed by a space (NOT a period, hyphen, or en dash). Eliminated the Copilot-via-GraphQL low-with-context regression and the PR Merge Cleanup mid-iteration regression; recovered Review Response Guide to ~100.

### Rules

- **author-model-declaration** — Every PR declares its author model via a `**Author-Model:**` line in the body (preferred) or a `Co-authored-by:` git trailer (fallback). Defines model families (anthropic, openai, google), plus a special `human` value that maps to no family, and mixed-authorship semantics so the paired reviewers can pick a cross-family reviewer and dodge self-review bias. Missing declaration blocks the PR via early `REQUEST_CHANGES` before the diff is read.
- **stateful-artifacts** — Cross-invocation JSON state files a skill writes and reads between runs. Every artifact has a documented schema, a single owner skill, a `schema_version` field, and a writer/reader contract. Artifacts are hints, not authority — verify against the live source before acting on a recalled value. Migrations happen under the owner skill, not as a side effect of unrelated runs.

### Rule tightenings

- **skill-authoring** — Document `user-invocable: false` as an optional frontmatter field for background-knowledge skills the runtime loads as context but the user should never invoke directly.
- **script-delegation** — Spell out the precheck-gating JSON contract with `wake_agent` as a boolean and `data` as an object (e.g., `{"wake_agent": true, "data": {}}` on the last line), the zero-token-cost rationale for no-op runs, and the single-fetch gate-and-payload pattern.
- **context-artifacts** — Enumerate the review rubric: frontmatter validity, sequential-execution preamble, flat step numbering, typed `Skill()` calls, silence-rule compliance, channel-appropriate formatting.
- **plugin-evals** — Reframe around the load-bearing shape: **task describes the SITUATION** (no technique), **criteria check whether the output matches the specific manner this tile prescribes** (flag choices, format literals, sequences, chosen identifiers). That conformance IS the tile's contribution — checking for it measures tile value, not testing reading. Bleeding is narrowed to strictly one case: a criterion literal appearing verbatim in the task description. Fix bleeding at the task (strip the leaked literal), keep the criterion. No-Leaking is narrowed to tile-internal implementation details only (action names, `.tessl/tiles/...` paths, tile-only identifiers); tile-prescribed conventions and invented literals are allowed — a competent engineer without the tile would not produce those specific choices, which is precisely why they measure tile value. Adds a "Lift, Not Attainment" section with a three-cause diagnosis for near-zero lift (coincidence with universal competence / task leaked the technique / criteria grade engineering-101 instead of tile-specific manner) — so "low lift = retire" is no longer the reflex; high-lift scenarios that test specific tile choices must be kept, not softened toward "testing reasoning". Includes the v0.1.1 → v0.1.19 regression diagnosis (lift halved from 26 → 13 absolute points) as the motivating data. The earlier in-session iterations that said tile-invented conventions were leaking or that criteria satisfied by grepping the skill files were "testing reading" were wrong and are superseded by this wording.

### Skills

- **install-reviewer** — Scaffold the paired gh-aw PR policy reviewers (OpenAI Codex + Anthropic Claude Code) into a consumer repo. Ships `review-openai.md` and `review-anthropic.md` as packaged templates; the skill copies both into the consumer's `.github/workflows/`, compiles atomically with `gh aw compile`, commits all six artifacts, and opens a PR. Each workflow runs `tessl install jbaruch/coding-policy` as a pre-step, then self-gates on the PR's `Author-Model:` declaration: the same-family reviewer emits a one-line "skipping: self-review-bias" COMMENT and exits; the cross-family reviewer reviews. Each reviewer's verdict now begins with a one-line load indicator (`"Policy loaded: N rule files from .tessl/tiles/jbaruch/coding-policy/rules/ (installed tile)."`), so a passing review visibly confirms `tessl install` reached the runtime. A missing or empty installed-tile path causes an early `REQUEST_CHANGES` with a diagnostic rather than a silent zero-context review. Preflight now emits a `warnings` array alongside `failures`; a committed root-level `.mcp.json` raises a `root-mcp-json-present` advisory (the Anthropic reviewer can't launch sandbox-unreachable MCP servers like `tessl mcp start`), and the install-reviewer PR body surfaces every warning verbatim in an "Action required before merge" section so the consumer acts before the first workflow run fails. The skill deliberately does not auto-modify the consumer's `.mcp.json` or `.gitignore` — the consumer decides. Three secrets required: `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `TESSL_TOKEN`. Clean-verdict reviews use `event: COMMENT` with a pass body (GitHub rejects `APPROVE` from `github-actions[bot]` with HTTP 422).
- **release** — Step 2 PR body template now includes a mandatory `**Author-Model:**` line per `rules/author-model-declaration.md`; Step 4 updated to describe the paired reviewers and their self-gating behavior.

### Evals

- **install-reviewer** — 3 scenarios graded against the paired-workflow layout: 1 positive (`consumer-scaffolds-policy-reviewer`) covering the happy path through preflight → branch → copy both templates → compile → commit all six artifacts → PR with the three required secrets (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `TESSL_TOKEN`) and the cross-family rationale, and 2 negative (`install-reviewer-refuses-overwrite`, `install-reviewer-missing-gh-aw`) covering the skill's two decisional guards.
- **Retired zero-lift scenarios** — removed `merge-with-failing-ci-rejection` and `release-on-main-branch-rejection`. Apr 18 eval run on v0.1.1 showed both scored 100/100 baseline, i.e. zero lift: the criteria grade responsible-engineer judgement (don't merge red CI, don't push to main) that any competent baseline LLM produces without this tile. Keeping them inflates the attainment average without measuring tile value.
- **Reduced task-level hints** — rewrote `coverage-gap-identification-and-fill` and `eval-scenario-quality-review-and-repair` to strip task text that enumerated the tile-specific techniques or defect taxonomy. Baseline agents can no longer pattern-match their way to the criteria from the task alone; the remaining scoring concentrates on tile-specific behaviour (correct weighted_checklist format, no bleeding in authored scenarios, negative-case coverage, discovering defects without being handed a taxonomy).
- **Restored tile-prescribed-conformance criteria on five scenarios** — after the corrected plugin-evals rule (see above) distinguished bleeding from conformance, restored specific-convention checks that were over-removed earlier. Each scenario now grades whether the output matches the specific manner the tile prescribes, NOT whether the agent can reason its way to some equivalent. Changes: (a) `pr-merge-and-post-merge-cleanup` — criteria now check `gh pr merge --merge --delete-branch`, `git pull --ff-only`, `git branch -d` (safe delete, not `-D`), `git remote prune origin`; (b) `review-feedback-addressing-conventions` — criteria check the tile's prescribed reply formats (`Fixed in <sha>` for accepts, `Declining — <reason>` for declines), with substance checks as complements; (c) `ci-and-review-status-polling` — criteria check the tile's prescribed mechanisms (`gh pr checks <N> --json name,bucket` with a caller polling loop, `gh api .../pulls/<N>/reviews`, `gh api .../pulls/<N>/comments`) with an explicit "NOT `/issues/<N>/comments`" check for the GitHub API trap; (d) `copilot-review-via-graphql` — criteria restore the tile's prescribed hot-path-plus-fallback bot-ID pattern (pinned `BOT_kgDOCnlnWA` with dynamic-discovery fallback) rather than the earlier "don't depend on hardcoded IDs" flip, which had inverted the tile's actual choice; (e) `version-bump-reasoning-and-manifest-upda` — task stripped of the "CI auto-bumps patch" leak (was teaching the agent the tile's policy inside the task text) so the agent must now apply that policy from the tile; criteria check the tile-prescribed CI delegation for patch, specific semver targets, and risk-based release sequencing. All rubrics still sum to 100.
